# List pages

- Pages that lists records should be navigable by the up and down button for selection
- Columns should be customizable via `ColumnsMenu` + `useColumnVisibility(key)` (`<ColumnsMenu columns={COLUMNS} {...columnMenu} />`). Every rendered column must be in `COLUMNS`. Toggling changes only the current view; **Save layout** stores it as the user's layout on the backend (`PUT /me/preferences/columns:<key>`, a JSON array of hidden keys; cached per user in localStorage so pages render before the fetch answers), **Revert to saved** and **Show all** reset it, and the button shows a dot while the view is unsaved
- There should be a search box for every page called the Global Filter. The search box searches all data even the user-hidden one. The Global Filter will search only at the frontend side
- The Column filters will query the backend for partial matching
- Date columns should be filterable by range. Add a utility for commonly used date ranges: Today, Current Week, Current Month, Last 30 Days, Last 3 Months, Current Year
- All lists should be by default paginated. Have 50 record per page as default. This should be supported by the backend
- All list and report pages should be exportable to a spreadsheet. The columns exported should be based on the visible columns. Export covers **all rows matching the current column filters across every page**, not just the page on screen — export handlers call `fetchAllContent(endpoint + filters)`, which pages through the backend (capped at 1000 rows per request) until the last page.
- Boolean columns should be filterable by True, False or non filtered
- All list and report pages have a **Reload** button (`src/components/ReloadButton.tsx`, placed just before `ColumnsMenu`, hotkey `R`) that calls `usePagedList`'s `reload()` — it re-queries the backend with the current page and column filters (the defaults if untouched), never resetting them. Pass the hook's `loading` (aliased `listLoading`, since pages already use `loading` for submit state) so the icon spins while the request runs.
- Wide tables go in `ScrollTable` (`src/components/ScrollTable.tsx`), which scrolls both ways inside its own box with a sticky header (titles + filter row) and no cell wrapping. Pass `activeIndex` so arrow-key navigation keeps the selected row in view. It needs a height-bounded parent: page root `flex h-full flex-col gap-6`, `Card` and `CardContent` `flex min-h-0 flex-col`, with `Pagination` after the `ScrollTable`. The page title sits on its own row above the toolbar (header `flex flex-col gap-3`), so a long title never wraps against the controls. Toolbars use `flex-wrap` so filters drop to a further line instead of overflowing. Pin one identifying column (e.g. Item Name, Reference #) with `PINNED_TH`/`PINNED_TD`, plus `pinnedKey` on `ColumnFilterRow`. Rows then need `group`, `data-active={i === activeIndex || undefined}` and an explicit `bg-[hsl(var(--card))]` before their hover/active backgrounds. Tables without a row-actions column pass `actions={false}` to `ColumnFilterRow`. Long free-text cells (Notes, Remarks) are capped with `<div className="max-w-xs truncate" title=…>`.
